# PROJECT STATE

## Overview
- Project Name: Wave Music (`spotify_pribadi`)
- Architecture: Standalone client-side music player (Zero-login, No-Firebase, 100% local persistence)
- Catalog & Streaming: Hybrid Engine (Deezer API + YouTube parallel search with relevance ranking) + Direct Progressive (`tag 18`/muxed MP4 for Otomatis) + audio-only ranged proxy for explicit 64/128/160 kbps, with resilient auto-recovery
- State Management: Provider (`PlayerProvider`, `LibraryProvider`)

## Critical Architecture Decisions
1. **Hybrid Search Engine & Metadata Hygiene**: `MusicService.searchMusic` queries Deezer and YouTube in parallel. Cleans titles (`cleanTitle`/`parseYouTubeMetadata`) removing amateur tags `[Official Video]`, `(Lyrics)`, etc. Filters out karaoke, lyric-only channels, and long compilations (>15 min). Scores and sorts tracks by relevance so official artist tracks rank first.
2. **Instant Playback & Mid-Song 403 Elimination**: `MusicService.resolveAudioStreamInfo` fetches YouTube manifests with `requireWatchPage: false` (reducing latency to ~350ms) and resolves progressive streams (`tag 18` or lowest-bitrate muxed MP4). `PlayerProvider._setStreamSource` feeds direct progressive streams straight to ExoPlayer via `AudioSource.uri(url, headers: ...)`, eliminating the local HTTP proxy burst limits (512 KB–1 MB) and stopping mid-track 403 buffer drops and infinite song restarts.
3. **Bulletproof Recovery & Position Preservation**: If network hiccups occur mid-track, `_scheduleMp4Fallback` forces a fresh signed URL (`forceStreamRefresh: true`) while retaining progressive stream priority and seeking directly to `resumePosition`. Retry attempts are capped at 2 per track to prevent infinite restart loops.
4. **Explicit Index Queue Navigation**: `PlayerProvider` uses `explicitIndex` for `playTrack`, `next()`, `previous()`, and `QueueSheet` tapping. Eliminates snap-back loops to earlier duplicate tracks in the search queue.
5. **Non-Blocking Asynchronous Local Audio Scanner**: `LocalAudioService.scanLocalAudioFiles` operates asynchronously via `dir.list(recursive: true)` stream, eliminating main-thread UI freezes and Android ANR prompts during deep storage scans.
6. **Offline Resilient Screens**: `home_tab.dart` and `search_tab.dart` isolate network operations in `try-catch-finally` blocks, transitioning smoothly to empty/offline states without indefinite loading spinners.
7. **Safe Lyric Query Sanitizer**: `LyricsService.sanitizeQueryTitle` cleans metadata brackets while safely preserving legitimate hyphenated words (e.g. "Spider-Man", "Anti-Hero", "Semi-Charmed Life").
8. **Bounded In-Memory Caching**: `MusicService._videoIdCache`, `_streamUrlCache`, and `SponsorBlockService._cache` are capped at 200 entries with automatic oldest-entry eviction.
9. **Integrity-First Offline Downloads**: `DownloadService` uses 256 KB ranged chunks, rejects HTTP 200 for non-zero offsets, validates `Content-Range` and total size, restarts from byte 0 when a 403 forces a container change, deletes `.download` temp files on failure, and writes exports atomically via a streaming `.part` file.
10. **Responsive Audio Watchdog**: Audio loading timeout set to 12 seconds (`_loadTimeout`), providing fast feedback if network is unavailable.
11. **Pre-caching Next Track**: `PlayerProvider` initiates background stream pre-fetching (`preloadTrackStream`) for `_queue[_currentIndex + 1]` upon playback start for near-zero latency track transitions.
12. **Diversified Track Radio**: `getRadioTracks` mixes artist-specific tracks with global chart tracks and caps each artist to a maximum of 2 songs, preventing homogeneous track flooding.
13. **Local Persistence**: All user data (Liked Songs, Custom Playlists, Recently Played) are stored locally via `LocalLibraryService` using `SharedPreferences`. No external cloud or database dependencies.
14. **Audio Export & Tagging**: Audio files are saved with native formats detected by header magic bytes (`AudioFormat.detect`). MP3 files receive ID3v2.3 tags (`Id3Writer`).
15. **Scoped Storage Permissions**: `READ_EXTERNAL_STORAGE` is capped at API 32 and `WRITE_EXTERNAL_STORAGE` at API 29. `MANAGE_EXTERNAL_STORAGE` is requested only for exporting to a user-chosen public folder or scanning local audio via `StoragePermissionService` (`com.david.spotify_pribadi/storage`); denied permission yields a clear error and an app-documents fallback.
16. **Android 13+ Media Notifications**: `POST_NOTIFICATIONS` is declared and requested at runtime after onboarding, so media controls can appear on modern Android lockscreens and notification bars.
17. **Audio Session & Becoming Noisy**: Listened to `session.becomingNoisyEventStream` and `session.interruptionEventStream` in `PlayerProvider` to pause on headset/Bluetooth disconnection and restore gracefully on call completion.
18. **In-App Version Checker & Battery Guide**: Added `UpdateService` querying `version.json` directly from the GitHub repository and intent launcher for Android battery optimization (Doze mode) settings.
19. **SponsorBlock Integration**: Integrated `SponsorBlockService` querying `sponsor.ajay.app` for active YouTube track to automatically skip skit, offtopic dialogue, non-music sections, intro, and outro.
20. **Two-Tier Priority Queue ("Play Next")**: Implemented user-priority queue (`playNext`) inserting tracks right after currently playing item before resuming background playlist context.
21. **Universal Playlist Backup**: Implemented `PlaylistBackupService` for two-way export and restore via JSON and standard M3U (#EXTM3U) formats.
22. **Audio Balance Removed**: The non-functional stereo balance UI was removed because `just_audio` cannot pan channels independently. `setBalance` remains only for backward-compatible state loading.
23. **First-Launch Onboarding & Disclaimer**: `OnboardingScreen` stores `has_accepted_terms_v1` and presents the educational disclaimer; `TermsDisclaimerDialog` provides the same notice for future entry points. It explains the educational/personal non-commercial scope, third-party stream origin (YouTube audio, Deezer metadata), copyright ownership, and user responsibility.
24. **Duo A (Rose & Obsidian) Visual Theme**: Replaced the previous green accent with Rose Pink (`#F43F5E`) and deep Obsidian charcoal surfaces (`#0E0E11` and `#16161B`) across `AppTheme`, custom painter waveform logo, equalizer controls, and modal dialogs. Maintained `primaryGreen` alias in `AppTheme` for zero-friction backward compatibility.
25. **Full-Screen Onboarding Walkthrough (3-Slide Carousel)**: Implemented `OnboardingScreen` (`lib/screens/onboarding_screen.dart`) replacing the startup modal popup. Features 3 responsive slides with custom visual motifs: Vinyl Record player (zero login & ad-free streaming), Studio Equalizer & Audio Engine (SponsorBlock & real-time lyrics), and Open-Source MIT License & Copyright attribution (David Yehuda Surbakti). Integrated `just_audio_windows` for Windows desktop audio playback.
26. **YouTube-First Search Ranking & Top Result Card**: Overhauled `calculateAuthorityBonus` to treat YouTube organic ranking as the definitive anchor authority (+85 for Rank #0, +55 for Rank #1, +38 for Rank #2) and eliminated Deezer false consensus traps (down to +15), guaranteeing canonical master releases (e.g. Oasis "Champagne Supernova") rank #0 over random covers and niche live sessions. Enhanced `cleanTitle` regex to strip video artifacts (`[Best Live Version]`, `| MTV Music`, `Lirik Terjemahan`) and soft-filtered lyric channels in `_fetchYouTubeSearch`. Retained the "Hasil Teratas" card with 68x68 cover artwork and "Rekomendasi Utama" pill badge.
27. **Universal Track Options Action Sheet**: Integrated `more_vert` (three dots) quick action button on both "Hasil Teratas" and "Lagu Lainnya" search results opening a Rose & Obsidian modal sheet (`TrackOptionsSheet`). Provides shortcuts for Like/Unlike, instant single-track offline download with status feedback (`downloadSingleTrack`), playlist management ("Tambah ke Playlist" with on-the-fly new playlist creation), Play Next, and Add to Queue.
28. **Interactive Swipe-to-Skip Gestures on Mini Player**: Implemented spring-based horizontal drag gestures with responsive cues and Rose Pink indicators in `MiniPlayer` to skip next/previous songs without opening the full player sheet.
29. **Interactive Tap-to-Seek Synced Lyrics**: Re-architected `_buildLyricsView` in `PlayerSheet` with per-line timestamp badges, instant tap-to-seek with playback auto-resume, subtle hint header, and complete Rose & Obsidian styling.
30. **Flexible Sorting & Filtering in Library Tab**: Implemented dynamic collection sorting modal and engine in `LibraryTab` for Liked and Offline tracks with real-time sorting by *Terbaru Ditambahkan*, *Judul Lagu (A - Z)*, *Nama Artis (A - Z)*, and *Durasi Lagu*.
31. **Transparent Smart LRU Audio Disk Cache**: `AudioCacheService` (300 MB bounded) downloads via ranged requests, validates total length and audio magic bytes, writes atomically through `.part`, uses stable FNV-1a filenames with real extensions, keys entries by track + quality, and closes its HTTP client. Replaying a cached song loads directly from disk via `AudioSource.file`.
32. **Dedicated Artist Profile & Discography Screen**: Implemented `ArtistScreen` with Deezer artist metadata API (`getArtistProfile`). Features full-bleed header artwork with gradient shading, monthly listener stats, verified artist badge, and ranked top 25 popular songs list. Accessible by tapping artist name in `PlayerSheet` and `SearchTab`.
33. **Zero-Second Premature Completion Guard**: Fixed an issue where selecting the top search result ("Hasil Teratas") or any song while player was idle skipped immediately to the next track. Root cause: `just_audio_windows` plugin emitted `ProcessingState.completed` on initial stream open because `session.Position().count() == session.NaturalDuration().count()` evaluated to `0 == 0`. Fixed with a dual-layer defense: (1) patched `player.hpp` in Windows plugin to require `session.NaturalDuration().count() > 0 && session.Position().count() >= session.NaturalDuration().count()`, and (2) added a robust guard in `PlayerProvider._initPlayer` (`lib/providers/player_provider.dart`) rejecting completion events if `_isLoadingAudio` is true or `_position <= 2 seconds`, and explicitly bound `explicitIndex: 0` in `search_tab.dart`.
34. **Chronological Liked Songs Ordering (LIFO / Timestamp)**: Added `likedAt` epoch timestamp to `TrackModel` and updated `LibraryProvider.toggleLike` to stamp current time when liking tracks. Configured `likedList` and `library_tab.dart` sorting mode 0 ("Terbaru") to order tracks descending by `likedAt` so newly liked tracks are immediately placed at the top (index 0), complete with `formattedLikedDate` display.
35. **Playback Robustness**: `_playChain` operations have a timeout, stale play requests are cancelled by token before touching the audio source, lyrics responses are ignored when the track changes, the active proxy source is closed on track switch/dispose, and crossfade/sleep-timer volume fades share a token so they cannot overwrite each other.
36. **Queue Integrity**: "Play Next" markers are tracked as a set of IDs rather than a counter, so removing, clearing, or trimming queue items cannot desynchronize the count. Insertion is stable even before a track is playing.
37. **Settings Persistence**: EQ, bass boost, crossfade, speed, pitch, audio preset, quality, shuffle, and loop mode are saved in `SharedPreferences` and restored at startup. Legacy "Maksimal/320 kbps" quality labels migrate to "Otomatis".
38. **Backup Format v2**: JSON backups now store playlists by ID with `name` + `tracks`; v1 name-keyed backups remain readable. Restore merges by default (dedupes tracks) or replaces when requested. M3U exports standard YouTube URLs/local paths instead of internal IDs.
39. **Stable Local IDs**: Local audio IDs use FNV-1a over the canonical path, and legacy `String.hashCode` IDs are migrated on library load so likes/playlists keep working across runs.
40. **SponsorBlock Correctness**: `actionType` is honored (`skip`/`full` only; `mute`/`poi` are not auto-skipped), caches have a 6-hour TTL (1 hour for empty results), and entries are bounded to 200.
41. **Update & Permission Hygiene**: App version comes from `package_info_plus`; update links must be HTTPS on the official GitHub repository path. Storage permissions are scoped by API level, and notification permission is requested at runtime.
42. **Bulk Download Feedback**: Failures are collected and shown in a summary snackbar instead of being silently logged.
43. **Documentation & CI**: Added `LICENSE`, `CHANGELOG.md`, `CONTRIBUTING.md`, issue templates, Dependabot, and GitHub Actions running `flutter analyze` + `flutter test` before building per-ABI APKs. Network-dependent YouTube tests are opt-in via `WAVE_NETWORK_TESTS=1`.
44. **GitHub Release Updater & Checksums**: `UpdateService` reads `version.json` from `raw.githubusercontent.com/yehudaaadev/spofree/main` and only opens HTTPS URLs under `github.com/yehudaaadev/spofree`, `raw.githubusercontent.com/yehudaaadev/spofree`, or `api.github.com/repos/yehudaaadev/spofree`. Update detection compares semantic `versionName` first because Flutter `--split-per-abi` offsets the installed `versionCode` by ABI (1000/2000/4000). Releases include `SHA256SUMS.txt`; the update sheet exposes a checksum button.
45. **Resumable Playback Session**: `PlayerProvider` debounces queue/index/position persistence to `SharedPreferences` (`wave_last_queue*`). On startup the last queue is restored without autoplay; pressing play resolves the stream at the saved position. Queue is capped to 100 stored entries around the active track.
46. **Lyrics Cache & Offset**: `LyricsLine` is serializable; lyrics are cached per track for 30 days (max 120 entries). Per-track offset (±5 s in 0.5 s steps) is persisted and applied to `currentLyricsIndex` and tap-to-seek (`lyricSeekPosition`).
47. **Storage Management Panel**: `StorageStatsService` combines `AudioCacheService` stats, downloaded-file sizes, and native Android `StatFs` free/total bytes. `StorageSheet` can clear the audio cache or all offline downloads and refreshes `LibraryProvider`.
48. **Wi-Fi-Only Downloads**: `NetworkStatusService` queries native `ConnectivityManager` (`ACCESS_NETWORK_STATE`). `LibraryProvider` rejects single/bulk downloads on metered networks with a clear `lastDownloadError`, configurable from the app info sheet.
49. **Release Signing in CI**: The repository has a permanent Wave Music release keystore (RSA 4096, valid until 2054) stored outside the repo, with all four Actions secrets configured. The workflow creates `android/key.properties` from `ANDROID_KEYSTORE_BASE64` and signs release APKs; without the secret it falls back to debug signing.
50. **Serverless Playlist Sharing**: `PlaylistShareService` encodes a playlist or the whole Liked Songs collection as `WAVE1.` + gzip + unpadded base64url. The compact payload keeps track ID (unless local), title, artist, album, duration, and YouTube ID; artwork is reconstructed from the YouTube ID. Decoding accepts a bare code, line-wrapped code, or a whole chat message containing the code. `LibraryProvider.importSharedCollection` creates a playlist or merges by case-insensitive name, dedupes by track ID, and does not duplicate liked tracks.
51. **Bounded Share-Code Decoding**: Validation covers format prefix/version, base64/gzip CRC, 200k-character input, 4 MB decompressed output via a bounded `Sink`, 1,000-track cap, control-character stripping, and field-length clamps. A gzip bomb is rejected before it can exhaust device RAM. Codes from a newer format version produce an update-app message instead of a generic parse error.
52. **Offline QR Sharing UI**: Each playlist row has a share action; the info sheet can share all Liked Songs and receive a code. `ShareCollectionDialog` shows a QR only when the code fits the 2,400-character comfort limit, with copy and native share fallbacks. `ReceiveCollectionDialog` supports paste, full-message paste, and QR scanning via `mobile_scanner`; `ShareCodeScannerScreen` ignores non-Wave QR codes. Camera scanning is exposed on Android/iOS/macOS; Windows can still paste and share text.

## Known Limitations
- Update flow opens the APK in a browser; it cannot download or verify the APK automatically. Checksums are provided for manual verification (`SHA256SUMS.txt`).
- Export to public folders still uses `MANAGE_EXTERNAL_STORAGE` (sideloaded app). A full Storage Access Framework migration is future work.
- Web is not a supported target (local file APIs and platform channels are mobile/desktop only).
- Crossfade is a fade-out, not true overlap; `just_audio` does not expose per-channel pan.
- APK binaries are no longer committed. `version.json` points to GitHub Releases, and the in-app update action only opens that page.
- The Android application ID, MethodChannel names, and preference keys still use `spotify_pribadi`/`spotube_*` for upgrade compatibility. Only user-facing branding was renamed to Wave Music.
- `getStorageStats` reports the internal data partition on Android; desktop builds show cache/download sizes without free-space statistics.
- The release keystore lives outside the repo (`release-keys/wave-music-release.jks` in the workspace parent). Losing it prevents signing updates with the same identity; keep a secure backup. Local builds without `android/key.properties` are debug-signed.
- Playlist share codes carry metadata only, not audio files or downloaded local files. A recipient still streams each track from YouTube and must download it again for offline use.
- QR sharing is limited to roughly 2,400 code characters; larger playlists must be shared as text. Camera scanning is not available on Windows, where paste/copy remains available.
- Bundling ML Kit through `mobile_scanner` increases release APK size by roughly 6 MB per ABI.
